# 下一步：128 次补充预实验

目的：上一轮每组只有 4 次，主要说明接口能跑通。本轮每组 32 次，查看合法代码率、
重复行为、随机审计样本数、费用和等待时间，为正式实验定规模。
四组共 128 次新增调用，仍使用 seed 11；这不是最终效果比较。

## 本地怎么运行

在已有项目的 PowerShell 中：

```powershell
cd 'D:\city(dg) study\AI\course-project\implementation'
python scripts/run_calibration_pilot.py
```

这条命令只预览：不输入密钥、不改账本、不访问 API。
正常会显示 `ready_to_activate: true`、旧请求数 16、新增上限 128、累计上限 144、累计费用上限 10 元。
旧费用按当时记录估算为 0.030928 元，实际账单以平台为准。

**愿意按这个范围运行时**，执行：

```powershell
python scripts/run_calibration_pilot.py --approve-128-calls
```

该参数明确授权新增最多 128 次请求。之后按提示隐藏输入 DeepSeek 密钥，输入时看不到字符是正常现象。
不要发密钥到聊天。空输入会退出，账本保持不变。

## 程序会做什么

1. 校验原 API 配置、原账本及普通开发/搜索/验证数据，test/OR3 不加载。
2. 创建一次运行标记，备份旧账本；在同一个账本内将总请求上限从 16 扩至 144。
3. 不清零旧请求或费用，累计金额上限仍为 10 元。只改变请求上限，模型、采样和价格字段沿用原配置。
4. 生成私有 `configs/calibration.local.json`，保留原 `api.local.json`；依次运行 A/B/C/D，各 32 次。
5. 保存提示、候选代码、原始响应、逐实例结果、随机审计与汇总。网络失败也计次，不自动重试。

输出目录为 `run_paid_calibration_时间戳/`，时间戳使用 UTC。
正常输出会逐组显示 `A_seed11` 等及 `32 candidate requests`；最后打印 `Calibration saved:`。
把最后的终端输出或 `calibration_summary.json` 发给我，我会读取其余本地日志继续分析。
不要发送私有配置或 SQLite 账本。

重复运行不会自动领取另一轮额度。有中断时保留 claim、备份、日志和账本，先定位原因，不能删除标记强行重来。
扩展后旧 16 次启动器会因配置签名不符而停止，这是预期行为。

## 分析时保持这些边界

- 32 次不会触发第 50 次的岛屿重置，也不足以证明长期搜索已饱和。
- 若随机审计为 0 次，误判率仍为 NA，不写成 0%。
- 搜索最优包含 BF 初始程序，追平 BF 不代表 LLM 产生了提升。
- 上一轮 16 次与本轮 128 次不拼接成一次正式搜索；分别报告。
- 价格估算沿用此前核验的未缓存高峰单价，未假定折扣；见
  [DeepSeek 官方价格文档](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)，核验记录为 2026-11-06。
  这不是平台账单保证；模型别名也不证明服务端不可变版本。

## 2. 20 元怎么花才不浪费

不要直接重跑 200 次 thinking 模式。那轮配置是 `max_tokens=32768`、`thinking enabled`、`reasoning_effort high`，输出一旦很长，单价 8 元/百万输出 token，200 次很容易超过 20 元，而且它的预算 guard 本来就不是按 20 元设的。

顺序应该是：

1. **0 元诊断**（本机先跑，不花钱、不发密钥）：
   ```powershell
   python scripts/check_deepseek_connection.py
   ```
   看默认路由和直连路由哪条通。401 = TLS 通了。
2. **1 次冒烟**（本分支新增 `scripts/run_smoke_test_1.py`，上限 0.50 元，独立账本 `configs/smoke1_budget.sqlite3`，1 次请求）：
   ```powershell
   python scripts/run_smoke_test_1.py
   python scripts/run_smoke_test_1.py --run --allow-paid
   python scripts/run_smoke_test_1.py --run --allow-paid --direct
   ```
   先默认路由跑 1 次；如果失败，再用 `--direct`（只在本进程内把 `api.deepseek.com` 加进 NO_PROXY，仍验 TLS）跑 1 次。两次结果一对比，就能分清是代理问题还是更上游的问题。冒烟只证明“通了 + 能生成”，不证明 A/B/C/D 有效。
3. **128 次校准**（如果冒烟通了）：按 `docs/CALIBRATION_20261107.md`，四组各 32 次，非 thinking，`max_tokens=1024`。按 11 月 6 日的用量推算，128 次大约 0.25 元量级，20 元绰绰有余。这一步是为正式实验定规模：合法代码率、重复行为、随机审计样本数、费用、等待时间。
4. **再冻结正式实验**：校准后定调用数、至少 3 个种子、模型与采样、已批准预算，按 `docs/FORMAL_PROTOCOL.md` 走 `formal.py freeze/run/seal/evaluate`。不要跳过这一步直接跑正式。

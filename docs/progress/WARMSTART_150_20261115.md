# 热启动组合进化 150 次/组：正式报告（2026-11-15 夜 – 2026-11-16 凌晨）

## 结论先行（负面结果）

**1800 次生成没有改进正式实验的优胜者。** 12 轮的 validation 入选优胜者中，
11 个就是种子本身（10 个是 B 组正式优胜者，1 个是 D_seed22 正式优胜者），
只有 1 个是新候选（A_seed33 candidate_000004，search 265.000，validation
267.7 = BF 水平，test 266.100 / OR3 209.95）。预注册标准 5 项中 2 项通过
（完成；search 均值微弱通过）、1 项失败（validation 更差）、1 项混合
（heldout 无一组双侧改进）、1 项通过（恰好 1 个新优胜者）。热启动组合进化
在这个设置下没有把正式优胜者往前推，进一步的 150 次/组投入回报极低。

## 问题与设计

正式实验（protocol 3eb1f24d…）的 12 个优胜者全部属于 sweet-band 家族，
最好 search 265.033。问题：从这些已验证的好机制出发，让模型在它们之间
组合、变异、继续进化 150 次/组，能否进一步改进？这是用户 2026-11-15 21:55
要求的“多种算法结合进化”的实现；文献种子方向已被证伪
（`docs/progress/LITERATURE_SEEDS_20261115.md`），故种子改用正式优胜者。

- **种子**：12 个正式优胜程序去重后 9 个不同代码（B 组 3 种子相同，C 组
  2 种子相同）+ FF/BF = 11 个种子，进入全部 4 个岛屿。代码逐字存入
  `funpack/programs.py` 的 `WARMSTART_SEEDS`，search 均值与密封值逐一核对。
- **提示词**：`mechanism_v3c` = mechanism_v3 文本逐字节不变 + 末尾追加一段
  “结合两个父代机制”的邀请。种子集合由 `enhanced_prompt_version` 决定
  （v3c → 11 个种子），由冻结协议固定。
- **规模**：4 arms × 3 seeds × 150 calls = 1800 次，0 元，Muse 模型
  （muse-spark-1.3，handshake 提供方）。
- **其余与正式实验相同**：seeds 11/22/33，islands 4，reset_every 50，
  audit_rate 0.1，temperature 1.0，disable_on_mismatch_v1，timeout 30s。
- **冻结协议**：`protocol-warmstart-150.json`，
  protocol_id `09cdd13bc48fa6e06ed92577dea70f690ccf810ce8040219faaed64e983c9280`，
  冻结于任何运行之前；冻结后代码未动（215 个测试全绿后冻结）。

### 唯一的新优胜者

A_seed33 candidate_000004（search 265.000，validation 267.7，test 266.100，
OR3 209.95），家族 `windows[8,20];[28,45]+dist+scaled`：

```python
def priority(item, bins):
    return [-(r - item) + (max(15, item / 2) if 28 <= r - item <= 45 else 0) - (max(15, item / 2) if 8 <= r - item <= 20 else 0) for r in bins]
```

仍是 sweet-band 家族，只是奖惩幅度随物品尺寸缩放（`max(15, item/2)`）——
是“组合”的真实实例，但 validation 未优于 BF，heldout 只比 B 种子好 0.033
（test）/ 持平（OR3）。

## 请求记账（1800 次）

- 成功完整评估 1425 次；精确文本缓存命中 80 次（A 组 66 次——基础组反复
  提出种子代码）；行为筛查跳过 294 次；格式违规 1 次（B_seed11 #33，
  Strategy 超词，已评估）；候选评估错误 1 次（A_seed33 #46，见上）；
  provider error 0；付费请求 0；花费 0 元。
- 筛查/审计：审计 42 次，**34 次存在任何不符（81%）**，C 组 17/17 全不符、
  D 组 17/25；禁用指纹 34 个；碰撞绕过评估 289 次。探针等价的前提比正式
  实验（16/27 = 59% 不符）失效得更彻底——筛查依然只丢候选、不污染分数，
  但 294 次跳过意味着只有 1425 次真正产生了新评估。

## 机制观察

- **B 种子是强吸引子**：sweet-band `[28,48]+15 / [8,22]−15` 在 10/12 轮中
  被选为优胜者。150 次进化没有离开这个家族——12 个优胜者全部属于
  sweet-band（含 A_seed33 的变体）。
- 协调员汇报反复提到：同窗口叠加奖惩会恶化（多次 265.5–269.3），后期融合
  转向门控取舍；容量比窗口、分布中心项（均值/中点/最松箱）明显最差
  （281.567 等）。生成器在组合上花了大量尝试，但 search 分布的顶端纹丝不动：
  11/12 轮的最好成绩恰好等于最优种子 265.033。
- 这与正式实验的结论一致：BF 在均匀随机数据上已近天花板；priority 函数
  的表达空间内，sweet-band 附近就是局部最优，组合现有机制不能跳出它。

## 缺陷披露

1. C 组 r1 生成器替换（脚本批量生成）——整轮作废，见执行日志。
2. 两次运行时重启导致 r1/r3 部分进度丢失；D_seed33 r1 的 264.967 未能保留
   （该成绩来自已作废/中断的轮次，不计入任何结论）。
3. A_seed33 #46：协调员的无效答案被流水线读走，浪费 1 次生成。
4. B_seed11 #33：Strategy 词数口径不一致导致 1 次格式违规。
5. C 组文件名 typo 导致两轮各停滞约 9 分钟（已改名修复，零损失）。
6. 合并时未推送 `run_warmstart/` 内复制的 12 个轮目录（与正式实验相同做法，
   可由 part + 合并脚本复现）；`data_reproduced/` 同样未推。
7. 审计前提失效（81% 不符）——筛查浪费比正式实验更严重。

## 对期中报告的意义

- **可以写**：热启动组合进化是经过预注册、冻结、密封、一次性终测的
  完整阴性结果：从正式优胜者出发再进化 150 次/组，没有改进 validation
  入选均值（267.692 vs 267.65）与 heldout（无一组双侧改进）；唯一新优胜者
  的改进幅度在噪声量级。这是一个合格的“此路不通”证据，与正式实验的
  结论互相印证（天花板在 BF 附近，机制空间已收敛）。
- **必须写清**：优胜者 11/12 就是种子本身——heldout 数字大部分只是在
  复述正式优胜者的成绩，不是新证据；新证据只有一个候选（A_seed33）。
- **不得写**：“上下文/组合改进了结果”、“热启动优于从头跑”（没有从头跑的
  对照组，本研究没有比较热启动与冷启动）。
